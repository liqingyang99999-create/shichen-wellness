# 内容库结构与维护

唯一运行数据源是 `server/catalog.json`。当前版本 `2026-11-04-lifestyle-qigong-v4` 包含 179 张基础行动卡、70 条来源、24 条节气内容和 12 个时辰主题。基础内容按 `origin` 分为传统动作／传统主题启发 72 张、现代日常 107 张；总数构成为 161 张一般候选卡 + 17 张意愿限定卡 + 1 张保留参考卡 = 179 张。一般候选卡按各自时段与条件参与；17 张意愿限定卡带有 `explicitOnly:true`，仅在用户明确表达对应活动意愿时参与。保留的通风参考卡 `23` 没有普通适用小时，不主动进入普通池。

时辰与节气用于组织文化和生活主题，不证明某时刻的经络状态、个体风险或行动收益。传统原文、现代科普和项目编写内容分别注明；依据传统主题设计的现代步骤不冒称古籍原始操作。来源的存在也不等于每张卡已经得到疗效验证。

## 数据表

| 集合 | 主要字段 | 用途 |
| --- | --- | --- |
| `cards` | `id,title,category,steps,scene,duration,sourceId,tags,hours,night,origin,requirements,mealPhases?,seasons?,explicitOnly?` | 固定动作、适用情境、时间、用餐阶段、季节与执行条件 |
| `sources` | `id,title,label,text,url` | 出处、主题或改写范围说明；项目编写内容允许没有外部 URL |
| `solar` | `term,date,quote,author,title,url,theme,action,base_ids` | 节气日期、诗句出处与当次提示；当前使用 2026 年上海日期 |
| `meridians` | `label,meridian,theme,start,end,ids` | 时辰标签、经络文化名称及内容组织主题 |

卡片的 `sourceId` 必须指向有效来源。`steps` 与 `duration` 是界面和 API 展示的固定内容；模型不能改写次数、力度、顺序或时长。`scene` 说明适用情境，`source.text` 说明出处与整理范围，`steps` 给出本次行动。

## 情境优先与用餐分期

最新明确的生活情境先决定内容主题，再在通过执行条件的候选中随机抽取。时辰组织文化主题，不能盖过“正在吃饭”“刚吃完饭”或“心情不好”等明确描述；吃午饭也不等于提供了具体钟点。默认使用当前真实时间，只有用户另填时间时才切换。

| 分类 | 当前数量 | 选用规则 |
| --- | ---: | --- |
| 餐前 `meal-before` | 17 | `mealPhases` 包含 `before`，明确准备进餐、选菜或做饭时选用 |
| 餐中 `meal-during` | 11 | `mealPhases` 包含 `during`；餐中只保留专心用餐行动 |
| 餐后 `meal-after` | 7 | `mealPhases` 包含 `after`；不继续推荐进餐步骤或食谱 |
| 情绪 `emotion` | 10 | 对应明确的情绪主题，其中部分兼用于餐中或餐后 |
| 节令食养 `seasonal-food` | 12 | 每季 3 张，仅在明确餐前情境中按季节优先选择 |

以上分类可重叠，不能直接相加作为总卡数。`mealPhases` 允许 `before`、`during`、`after`；未知阶段不匹配带有该字段的卡。`seasons` 允许 `spring`、`summer`、`autumn`、`winter`；使用当年节气数据中的立春、立夏、立秋、立冬分季。缺少相应年份的节气数据时，不宣称已精确匹配该年节令。

餐中不会混入闭目、专门呼吸练习、走动或书写任务。最近 3 张仍参与去重；不足时保留真实缺口，不靠跨用餐阶段抽卡填充。当前餐后低条件卡 `MA001`、`MA004`、`MA005`、`MA006` 可在活动条件未知时用于餐后收尾或回顾；需要走动、漱口或整理的其他卡继续检查其条件。

## 四季食养内容

`F001`–`F012` 使用普通食材：春日蔬菜卷、菠菜鸡蛋汤和豆芽鸡丝饭；夏日冬瓜豆腐汤、丝瓜炒蛋和青菜鸡丝面；秋日南瓜小米粥、莲藕瘦肉汤和山药胡萝卜饭；冬日白菜豆腐煲、白萝卜牛肉汤和香菇鸡肉饭。它们用于为原定的一餐选搭配，不因某个时辰或天气额外催促进食。

这些卡片的时长是“约30秒选定；烹调另计”，不是承诺在 30 秒内做熟一餐。具体组合属于参考膳食原则整理，来源说明区分文章中的食材建议与项目编写的步骤；不编造古籍原方、药材剂量或食物治疗作用。按本人过敏及特殊饮食限制选择，相关卡注明鸡蛋、大豆或小麦等配料，外食需核对食材及调味料。

## 生活创意与八段锦单式

`L001`–`L009` 分别对应三行日记、拍照、简笔画、泡茶、联系亲友、轻柔拉伸、照料植物、发呆和鲜花；`L010`–`L017` 对应八段锦八式。全部设置 `explicitOnly:true`。每张恰好含一个生活活动标签：`journal`、`photo`、`drawing`、`tea`、`family`、`stretch`、`plants`、`daydream`、`flowers` 或 `qigong`。可兼用 `quiet`、`emotion`、`environment` 等一般标签，八段锦不再兼用 `stretch`，避免想做普通拉伸时误入八段锦。

用户表达当前、本人愿意做某类活动后才启用对应候选；否认、他人的活动和单纯未来安排不视作本次意愿。活动意愿不能代替物理条件：泡茶和浇花检查是否方便取水，拉伸与八段锦检查可站起和空间，发呆卡要求坐稳，八段锦第八式另需固定扶手。条件未知时保留缺口，不推断已有。电话、茶、植物、鲜花与站姿练习设置各自日间时段，不能因为明确请求就绕过睡眠、餐中或交通专注限制。

八段锦点名某一式时，按规范名称或明确序号匹配该式；只说想练八段锦时，在满足条件的八式候选中选择。八式规范名称为两手托天理三焦、左右开弓似射雕、调理脾胃须单举、五劳七伤往后瞧、摇头摆尾去心火、两手攀足固肾腰、攒拳怒目增气力、背后七颠百病消。式名保留传统称呼，不作为效果承诺。卡片为少量、舒缓体验，热身另计；转颈、摇摆和俯身的复杂动作，初学先看规范示范，不凭短文强行尝试。

动作核对使用[北京体育大学公开教材八段锦章节（PDF 页 123–133）](https://www.bsu.edu.cn/docs/2020-03/340c93f032b34f69add36bb8b77f587d.pdf)、[中国健身气功协会教学文章](https://chqa.org.cn/html/109013-72972.html)与[国家体育总局定式页](https://www.sport.gov.cn/n20001280/n20001265/n20067611/c20106840/content.html)。卡片“查看出处”提供[协会规范演练入口](https://www.chqa.org.cn/html/109014-448973.html)。采用自然呼吸、小幅度与较高站姿；第八式扶稳、控制落下的操作是项目舒缓体验改编，不冒称完整规范套路。

其他生活创意明确标为项目编写，不附会古籍或治疗作用。茶温适口、不强推浓茶或睡前含咖啡因饮料；浇花先确认品种和土壤，土湿不浇；买花先设预算，允许只看不买。拍照、记录、电话和购买由用户在自己的工具中操作，应用不会自动执行。

## 执行条件

`hours` 明确列出 0–23 的小时。空数组表示不进入普通池，不能解释为全天。`night` 表示是否可进入夜间轻行动池；不覆盖用户的睡眠、勿扰或暂停状态。

```json
{
  "requirements": {
    "trueFields": ["sitting", "canCloseEyes"],
    "falseFields": []
  }
}
```

上例要求明确坐稳且可闭目。天气相关动作可另加 `weatherFresh:true`；不依赖天气时应省略该字段，`false` 代表要求天气状态不新鲜，并非“不检查天气”。`trueFields` 要求字段严格为 `true`；`falseFields` 要求严格为 `false`；缺失或未知都不能充当已确认值。

支持条件：`canLeaveSeat`、`canLookFar`、`canCloseEyes`、`sitting`、`spaceEnough`、`hasSupport`、`waterAvailable`、`headphones`、`atMeal`、`goingOut` 以及 `weather.rain`。存在显式 `requirements:{}` 表示没有额外声明条件；没有此对象的旧卡才使用兼容规则。新增内容统一使用声明式条件。

## 编辑与验证

1. 检查候选动作是否与现有步骤重复；不要仅换标题增加数量。
2. 确认来源能支持所写主题，并在 `source.text` 说明哪些是现代整理。未找到外部原文时写清项目编写，不伪造出处。
3. 写明可执行的固定步骤与场景，设置真实需要的条件；不要通过取消条件或随意扩展小时掩盖候选不足。
4. 用稳定、唯一的 ID 关联来源，检查 `origin`、标签、适用小时和夜间属性，并更新内容版本。
5. 运行 `npm test` 和 `npm run audit:coverage`。结构与重复检查验证关联、已知条件字段和归一化动作文本；覆盖审计检查 24 小时、夜间属性、执行条件和各类明确情境，记录候选不足。更改标签或可选字段时，同步维护 schema 和相应测试。

一般场景目标是至少 8 张候选，明确而狭窄的情境单独检查。单卡生活意愿可以在用户再次明确请求时有意重看该卡；八段锦点名某式也可复看，不能为了去重换成用户没点名的另一式。为了在任意最近 3 张之后仍有可选项，连续轮换场景至少需要 4 张实质不同的适配卡；不能为凑数取消条件或仅改写标题。阶段、季节和执行条件可能进一步缩小候选，缺口以实际报告为准。该覆盖检查只评价候选可用性，也不取消睡眠、勿扰、每日次数或间隔限制。生成报告位于 `test/reports/coverage.json`；报告与实际测试日志一起解读，不能把模型模拟响应当作真实 AI 联调。

内容同时服务网页、Android 容器和现有只读智能体 API；扩库没有取消 API，调用参数和鉴权见 [agent-api.md](agent-api.md)。0.4 本版新增语音转文字入口，转写仍须用户手动发送后才参与情境识别；设置中的检查更新也不改变内容过滤规则。
